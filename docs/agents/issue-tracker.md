# Issue tracker

Issues and specifications for this repository live in GitHub Issues. Infer the repository from the configured Git remote when using GitHub tooling.

## Working conventions

- Read an issue and its comments before implementing it.
- Keep the issue body focused on the outcome, acceptance criteria, and relevant constraints.
- Use labels from `docs/agents/triage-labels.md`; do not assume an unlisted workflow label exists.
- Record material scope decisions in the issue or repository documentation.
- Close an issue only after the requested work is verified and published when production verification is part of its acceptance criteria.

Pull requests are not used as a general request or triage surface. GitHub Issues remain the source of work specifications.

## Larger initiatives

When one initiative needs multiple tickets, use one issue as the map and link the implementation issues from it. Record blockers explicitly in the issue body when native issue dependencies are unavailable.
